# T8.4 — Target-location impact evidence

`/events` now shows an evidence report for the configured target location. The report calculates the latest observed storm-centre distance and the signed change in that distance between the last two observed points. A negative change means the centre moved closer over that interval; it is not a future-track prediction. When official and model-guidance points exist for the same valid time, the report shows their maximum separation. Repeated issues from one source use its latest issue for each valid time.

For the 24 hours ending at the latest event position, the report reads only validated, non-interpolated weather rows for the **exact configured location**. It selects one source with the most usable hours, rather than mixing sources. It reports available humidity, cloud cover, and surface-wind means with their sample count. It reports a 24-hour rainfall total only when all 24 one-hour precipitation intervals are present and aligned with their UTC hour-end timestamps. Partial or invalid rainfall is shown as a gap, not a zero or a complete daily total. The source and available raw-payload references are displayed. `open-meteo:era5` is explicitly identified as historical reanalysis, not a rain gauge.

The assessment status is currently `insufficient_evidence`: no forward local rain-model field, upper-air flow, terrain-response model, or validated event-to-local-rain relationship is installed. An event's existence, proximity, approach, cloud cover, or historical coincident rainfall cannot by itself establish future local rain or causality. The UI therefore shows no impact grade or rain probability. [T8.5's historical event/rain analysis](EVENT_RAINFALL.md) did not beat its baseline in the current holdout; a future sourced and validated model can add a separate prospective assessment without reinterpreting this evidence inventory as a forecast.
